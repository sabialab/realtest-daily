# 写稿细则

主文件第 5 步的展开。

## 标题：先说交付物

**读者能拿到什么，进标题；过程亮点再精彩，只进正文。**

对着草稿问一句：*读者看完标题，知道自己能拿到什么吗？* 答不上来就重写。

三条连带纪律：

- **正常速度不许渲染成落差**。「30 秒装完」如果是这类工具的常规速度，那它不是卖点，写进标题就是骗点击。
- **被测对象要报名字**。标题、首屏、口播三个位置里至少两个出现工具的真名——读者搜得到才有二次流量。
- **收费的必须在标题或首屏明示**。

### 标题公式（挑一个，别叠）

| 公式 | 形状 | 用在 |
|---|---|---|
| 交付物前置 | 「<一句话成品>，<成本/门槛>」 | 可展示物很硬的期 |
| 反预期 | 「我以为要 X，结果 Y」 | 有真实翻车或意外读数 |
| 数字锚 | 「跑了 N 次，只有 M 次…」 | 有多轮真实读数 |
| 挑衅体 | 「别再 X 了」 | 有明确错误示范可打，慎用，一个月别超一次 |
| 身份钩 | 「不会写代码的人怎么…」 | 零基础向 |

## 开头：三秒内给出一个具体的东西

第一句禁止出现：背景铺垫、行业现状、「随着 AI 的发展」。

四种能用的开头：

- **结果前置**——先把跑出来的成品/读数摆上。
- **场景钩**——一个读者今天真会遇到的具体麻烦。
- **反常识**——一个跟大家默认认知相反的实测事实。
- **自曝**——「我这步做错了三次」。

## 结尾：一个问题，不是一段总结

- 结尾禁止重新概括全文，禁止升华到时代尺度。
- 互动题的结尾问题要**尖到能一句话回答**——「你会用它做什么」太宽；「你手上有哪份表是每周都要重做一遍的」才有人回。

## 多平台分稿

同一份实测，三种形态，**不是同一篇稿复制三份**：

| 形态 | 长度 | 写法 |
|---|---|---|
| **长文**（公众号/知乎/博客） | 1200–2500 汉字 | 全篇保姆级。每一步都要能照做，截图指代清楚。这是唯一能承载完整实测过程的形态。 |
| **图文笔记**（小红书类） | 300–600 字 | 首屏三行决定生死。分段短、口语、可带 emoji 当语气（别拿它装饰标题）。**平台外链是硬伤**——外站平台名、二维码、「搜 xxx」一律不要。 |
| **短帖**（X/微博类） | 单条自足 | 一条讲完一件事，不做长串。第一行就是结论。 |
| **口播视频**（可选） | 40–90 秒 | 一句一镜。证据画面必须能回源到真实测记录。 |

### 平台外链纪律

图文平台（尤其小红书）判据只有一条：**读者会不会被这句话指引离开这个平台**。会，就删。

- 删：外站平台名的导流性提及、二维码、「搜 xxx」、仓库链接。
- 留：题材本身必须提到的产品名（只提及、不导流）。

链接放长文和短帖，不放图文笔记。

## 换元三步的验收

写之前把三行写清楚，写不清楚就是还没想好：

```
抽骨架：<对标爆款的结构，一句话>
换血肉：<换成我的赛道之后是什么>
加料：  <我今天跑出来的、别人抄不走的那一条>
```

「加料」那行如果填不出东西，说明第 3 步实测挖得不够深——回去挖，别硬写。

## A/B 对比：给结果，不给实验手段

做横评时，读者要的是「哪个更好、好在哪」，不是你怎么控制变量的。

实验设计写进实测记录，稿子里只出结论 + 一处能看的证据。写完默读一遍，凡是「为了公平起见我把两边都归一到…」这类句子，全删。
