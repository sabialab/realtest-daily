# 视频产线

主文件第 5b 步的展开。把一次实测做成一条能发的片子。

技术栈假设 **Remotion**（React 渲视频）。换框架的话，除「工程规范」一节外都通用。

> 这份讲**判据**。要落地成一条真能派活的产线（房规层、派工单七节、施工图骨架、自家卡写法、收货 QC 分界），读 [`../shotcraft/`](../shotcraft/)——它是我们在开源镜头卡库 [video-shotcraft](https://github.com/Vincentwei1021/video-shotcraft) 之上那一层的开源版。

## 一、先定位：品牌化重演 + 证据窗

这是整条产线的地基，也是最容易做错的一件事。

**片子里的画面分两类：**

- **重演件**——你自己写的组件（拟真窗口、卡片、图标、动效）。它们是**品牌化重演**，好看、统一、可控，但**不单独作实测证据宣称**。
- **证据窗**——承载「这事真发生过」的那一块。

**证据窗默认由拟真组件逐字重演真实运行记录**，而不是直接贴截图。为什么：真截图上屏经常是英文满屏、字太小、色调不统一、还带地址栏。用你自己的组件重演，视觉统一、字能放大、能加中文标注。

**代价是必须有一道回源闸**：屏上每一个字都从一份**真值表**里抄，逐字不许改。

```
truth.md（真值表，从 test-log 摘出来的真实输出，一字不改）
   ↓ 抄
组件里的文案常量
   ↓ 脚本比对
回源比对脚本：屏上文本 ∉ 真值表 → 报错
```

**没有这道闸，「重演」就等于「编」。** 这是这套做法唯一的风险点，必须机器守。

**什么时候用真截图原图：**

- 用真截图**不需要理由**——想用就用。
- 但截图类必须**窗内取景到局部** + 配中文标注，别整张贴上去让人眯眼睛。
- **整图铺满只许一种东西**：被测工具自己生成的产物（它出的那张图、那条片）。那是真证据，铺满合法。

**存档面 vs 屏上面**——两件事，别读串：

| | 存档面 | 屏上面 |
|---|---|---|
| 是什么 | `images/raw/` 里的真截图、test-log | 成片画面 |
| 证据链认什么 | **只认真截图** | 重演件（回源真值表）＋真截图 |

## 二、四阶段两审核点

**审核点是给人留的，不是给 Agent 留的。** 一条片子只值得人看两次：

```
阶段 1a  写剧本 + 口播稿 → 停
阶段 1b  合成口播 + 配乐 + 混一条样带 → 【审核点①：读剧本 + 听样带】
阶段 2   施工渲染 → 收货 QC → 【审核点②：批成片】
阶段 3   （可选）补其他画幅
```

**审核点① 放在合成之后、渲染之前**，这个位置是有讲究的：剧本改一个字，后面全部重来；而听样带只要两分钟。把判断放在最便宜的时点。

**审核点② 之前必须先过收货 QC**——人不该是第一个发现问题的人。

三条纪律：

- **横版没过审，绝不去补竖版**。补了也是白补。
- **剧本一旦过审就冻结**，字幕、时间线、帧表全部锁在那一版上。要改就退回审核点①重走。
- **人改过的东西不许回滚**。你手改了一句台词，后面任何自动流程不许改回去。

## 三、反 PPT（这是最难的一关）

「太 PPT 了」是这类片子最常见的差评，**根因几乎总是镜数不够**。90 秒的片子只有 9–10 个镜，就是一页一页翻。

四件套：

1. **每个场景全程缓慢推近**（scale 1.0 → 1.05–1.08），不是静止。
2. **重击帧衰减震动**——切点上给 7px 左右的位移，快速衰减。
3. **大字金属光扫**——标题字上过一道高光。
4. **硬切，且切点全部落在音效重击上**。

文字入场必须**复合运动**（缩放 + 位移 + 模糊 8px→0），**禁纯淡入**。

### 但运镜必须「落定」

镜头动完要停住。**永不落定的慢爬是另一种病**——整场 90 秒缓慢爬行，观众看着累，证据窗里的字还会飘到糊。

```js
// ✗ 爬满全场，永不落定
interpolate(frame, [0, 场长], [1, 1.3])

// ✓ 前 12 帧推到位，之后 hold
interpolate(frame, [0, 12], [1, 1.06], { extrapolateRight: 'clamp' })
```

**证据窗尤其要落定**：观众要读窗里的字，字在动就读不了。做法是硬切到目标区域 → 窗内微推 → ≤12 帧落定 → hold 住。

**这一条机器很难判，静止检测和帧差探针都测不出「漂移」**——必须有人真的看一遍。

### 版面：整屏只干一件事

- 主标题 100–160px（爆点数字可以 200px+），副标题 48–72，正文 32–40。**任何文字 <28px 即 bug。**
- 内容占满画面（两侧留白 ≤300px、纵向填充 ≥70%）。不够就**放大字号，不许加内容凑**。
- 常驻元素（标题牌、字幕带、角标）**不要超过一条**。三条常驻带一起挂，整屏就没了。
- 常驻层放在相机之外——标题牌和字幕带不跟着镜头动。

## 四、声音（要点；全流程另见 `narration.md`）

> 从剧本到混音样带的完整作业——落笔法、六条自查、两把外部尺子、打标记、合成、
> 字幕冻结、BGM 竞标、混音与提审——在 [`narration.md`](narration.md)。这一节只留最容易踩的几条。


- **口播响度全片一致**。忽大忽小是最伤的听感问题，逐行做增益归一，别用降频那种偷懒办法。
- **字幕是冻结件**：口播定稿后生成一次字级时间戳，之后字幕、帧表、音效卡点全部锚在那一份上。
- **BGM 要 duck**——压到口播底下（经验值 0.1 上下），不是「小声一点」。
- **BGM 禁人声**。这条要机器判：拿 ASR 去转一遍候选曲，转出词就是有人声。⚠️ **中文演唱的坑**：不给 ASR 指定语言时，中文演唱常被识别成 `[Music]` 判成「无人声」——这道闸会对中文歌**系统性假绿**。要么按素材语种传参，要么用 auto。
- **短音效（<1s）不要用 integrated 响度归一**——太短算不出积分响度，会返回 `-inf` 然后把增益推到削顶。短件一律用峰值归一。
- **屏上文字不与口播同源**。字幕已经在念台词了，画面上再把同一句话写一遍，等于整块画面白给。

## 五、工程规范（Remotion）

- **先装官方 Agent Skills**：`npx skills add remotion-dev/skills`。它把 Remotion 的硬约束写成了官方原文（禁 `Math.random()`、禁 CSS transitions/animations、禁 Tailwind 动画类名、`interpolate()` 必带 clamp）。**Agent 写 Remotion 翻车的主因就是缺这一层。**
- **版本精确锁，禁用 caret**。`^4.0.x` 会让新工程漂到别的小版本，触发混装警告，然后 Agent 会误诊成「这个 API 不支持」把正确代码删掉。改完 `package.json` 记得 `npm install --package-lock-only`。
- **一次性事件要加帧门控**：`frame >= 触发帧`。clamp 的 `extrapolateLeft` 会把事件值钉在触发之前，白闪会在片头就闪一次。
- **禁双框架混渲**。别把别的框架的产物合进来——视频路径有色偏（同一文件 ffmpeg 解码正确、渲染器解码走 tv-range 会偏），品牌色直接不准。万不得已只走 **PNG 序列**，ProRes/WebM 一律不用。
- **多画幅一次出**：同一工程注册多个 Composition，场景组件共享，用 `useVideoConfig()` 做响应式排布。**绝不写两套场景。**
- **单一事实源**：所有逐字文案集中一处；帧表是唯一时间锚点，音效卡点一律写成 `帧表.sX + 偏移`。改节奏只动表。
- **重场景加 `<Sequence premountFor={30}>`**，资源用 `staticFile()`。注意 `premountFor` 在 `layout="none"` 的 Sequence 上不存在，硬加会 TS 报错——字幕那种别加。

## 六、收货 QC

**渲染交给谁都行**（另一个 Agent、另一个 CLI、你自己），但**收货必须你来**。

按成片标准**一次渲完整片**，不要分段渲了再拼——拼接点的音画偏移是最难查的一类问题。

### 机器能量的（脚本跑，必须全绿）

1. **时长/画幅/码率**对不对。
2. **响度**：整片积分响度与峰值上限。
3. **文本回源**：屏上每个字在不在真值表里。
4. **素材门**：引用的每个音频/图片在不在盘。
5. **静止检测**：有没有连续 N 帧画面零变化（死画面）。

### 只能人看的（机器面是空的）

1. **遮挡与裁字**——字幕压住了内容、长标题被切掉。
2. **露底**——图没盖满取景框，露出背景色。
3. **中文错字**——抽帧逐字校对，**一票否决**。
4. **画面单不单一**——同一个组件反复用，观众会觉得「就这一招」。

第 2 条特别值得说：**露底在机器面是空的**，四轮 QC 全绿也能漏到你眼前。想加闸就判「四边死带的颜色是不是父层底色」，**别用梯度量法**——纯色和渐变背景会全部假阳。

## 七、常见翻车清单

按踩过的次数排：

1. **镜数不够**（→「太 PPT 了」）。90 秒别少于 20 个镜。
2. **执行体自建通用组件顶替你的组件库**——卡名对得上、实物不对。要判就得让组件在源码里留下可 grep 的锚，光看它自报的卡名没用。
3. **同一张卡反复用**——单期同一个内容组件用 ≥4 次就该报警。
4. **运镜爬满全场不落定**（见第三节）。
5. **复制模板工程时带进上一支片的音频/字幕/时间线**——`cp -R` 会把上一期的整套声音资产一起带过来。加一道「这些素材是不是本期的」检查。
6. **自报值当读数用**——渲染方在配置里写 `motion: "MOTION"`，实测那一镜连续 4 秒零变化。**要么现量，要么标注「自报未验」。**
7. **地址栏**——自己画的浏览器地址栏也算导流面。窗口件本身（标题条 + 三个圆点）没问题，地址栏、页签、锁图标、任何可读 URL 都不行。

## 八、别做的事

- **别为了用某个效果加片长**。加长的应该是成品在屏上的时间，不是嘴闭着的时间。
- **别在日更窗口内改量具**。新闸当天上线当天判错的概率极高。要改闸，**先拿存量的片子跑一遍正对照**——历史上判绿的片子不能因为你加了个规则集体翻红。
- **别信「这次成功了就写进正本」**。单期成功不是规律，至少看三期。
