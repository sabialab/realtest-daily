# 四阶段两审核点

上游的八阶段是**方法**，由执行体在你的「阶段 2」内跑完。这份只管**交接**——谁在什么时候把什么交给谁。

## 阶段表

| 阶段 | 谁做 | 产出 | 闸 |
|---|---|---|---|
| **1a 剧本** | 你（或你的写手 Agent） | 剧本 + 口播全文初稿 + 外部审校意见落盘 + 机器检查读数 | 口播审校判「过」，或「打回 → 按清单改完销账」 |
| **1b 声音** | 你（要读密钥的都在这一侧） | TTS 正式合成 + BGM 竞标 + 混一条样带 | **审核点①＝人读剧本 + 听样带**。批准前不许开工渲染 |
| **2 施工渲染** | **施工方**（另一个 CLI／Agent／你自己） | 横版母带 + 回执 + `shots.json` | **审核点②＝人批成片**；批之前先过收货 QC |
| **3 竖版** | 施工方（同法再派一轮） | 竖版母带 + 接触表 | 竖版专属防线逐格通读 |

## 审核点为什么放这两个位置

**审核点① 在合成之后、渲染之前。** 剧本改一个字，字幕、帧表、音效卡点全部重来；而听一条样带只要两分钟。**把判断放在最便宜的时点。**

**审核点② 在收货 QC 之后。** 人不该是第一个发现问题的人。收货 QC 抓不出来的才轮到人看。

## 不可跳的边界

- **两个审核点由人本人批**，Agent 不得代批、不得合并。
- **横版未过审绝不补竖版**——补了就是在错误的底片上做两遍。
- **密钥红线：施工方绝不读你的 `.env`。** TTS／BGM／混音全留在你这一侧。派出去的只有「渲画面」这件事。
- **派工单只给约束不给逐镜数值表**；施工方照上游卡自判，回执逐镜写理由。

## 施工方按成片标准交付，不渲两次

**整片一次渲完**：

```bash
npx remotion render src/index.ts <comp> out/<comp>.mp4 --codec h264 --concurrency=4
```

- **禁 `--frames=` 分段 + concat 拼接**，禁跨轮借上一版的尾段。拼接点的音画偏移是最难查的一类问题。
- 渲不动了（并发崩／字体 `delayRender` 超时）就**停下报出单人**，不拼、不自改并发。
- **母带链参数由施工方逐字照抄自跑**，收货侧不再整渲、只复核。先读积分响度，再按目标值算增益 + 限幅出母带。
- 回执里固定写一行：`render 命令原文｜源 I/LRA｜增益 dB｜母带 I/LRA/max_volume｜md5`。**收货侧对同一份 md5 对账，对不上＝没交。**

早期我们是「施工方渲一版、收货侧再整渲一版」。那是过度工程——同一份源码渲两次，第二次只是为了让收货方安心。改成施工方按成片标准交，收货侧 `--no-render` 全检 + md5 记账。

## 收货 QC

### 机器判（脚本跑，必须零 ✗）

1. **素材在位**——引用的每个音频/图片/字体在不在盘。
2. **字幕全覆盖 + 时间线与口播对齐**。
3. **文本回源**——屏上每个字在不在真值表里。
4. **证据窗契约**——证据镜有没有被套上镜头层（该静的地方在动）、取景键是不是内联字面量、截图类有没有整图铺满。
5. **镜表契约**——`shots.json` 结构、一件一卡、同一张内容卡重复次数。

⚠️ **素材门在 `--no-render` 下照跑**——它判的是「在不在盘」，跟渲不渲染无关。

### 人判（机器面是空的）

1. **取景框有没有切到正文**。
2. **深底上的角标对比度**——纯色和渐变背景会让所有梯度量法假阳。
3. **卡片倾斜/透视是否成立**——三面（正面、侧面、投影）关系错了机器一点感觉都没有。
4. **画面单不单一**——多卡去重只证明没机械复用，不证明观众持续看到变化。

我们有过一轮**机器五道全绿、人判六红**。别把「全绿」当成「可以给人看了」。

## 派完之后

- **全量复核每轮都跑，别等人判词回来再跑。** 两条线并行，不要串行。
- **派两判时点名要看什么**——「你看一下有没有问题」得到的永远是「没问题」。
- 施工中途配额断了、进程挂了，定位断点看三处：产物在不在、执行日志最后一条是什么、命令序列日志跑到哪一行。
