## 意图
证据窗是全片唯一被红线锁死「内容必须回源到真数据」的一格。它的任务是**让人读清那几行字**，不是表演运镜。

有一轮我们给 14 个证据窗套了张力相机卡，推到 1.18–1.45——真截图裁字、A/B 并排失效、露出背景底，判词是「证据框在飘，不如第一版」。本卡就是那次返工的成文形态：**证据镜的相机几乎不动，动的是内容层。**

## 做法
- 相机：硬切到区域（第一个取景键）→ 窗内微推（首尾缩放比很小）→ 短促落定 → hold。**不套通用相机组件。**
- 内容零出画：窗框／标签／徽章／扫描线／文字每一帧完整在画幅内，不压标题牌下沿与字幕带。
- 运动感来源（鼓励用足）：光标一次定向点击、扫描线、标签弹立、快闪计数、点亮、滚数。
- 图在窗内：截图类一律走取景键（组件内 CSS `zoom`，取景框由偏移＋缩放定）；只有「产物」目录下的东西才整图铺满。**组件不提供 `cover`。**

## 组件与机器面
窗容器组件必填证据属性（`raw:<file>` 原图 / `recon:<file>` 重演）；几何常量去组件头注读，**不自造数**。窗里的内容默认是拟真组件逐字重演（真值表 → 数据模块 → 回源脚本）。

契约：证据锚为内容的场景，**同文件内禁套通用相机组件**（豁免按镜号点名，不许通配）。另有静态判：①取景键必须是内联数组字面量（`keys={someVar}` 判红——变量指过去的东西机器读不到）②首尾缩放比与落定帧数各有上限（**判首尾不判相邻**）③截图类无取景键且不在「产物」前缀下判红。

## 已知坑
- 「给证据镜一条完整相机弧」是被实证推翻的口径，**别照旧 spec 的作废行施工**。
- `transform: scale` 放大真截图＝糊字（先按原尺寸栅格化再放大）。缩放一律走 CSS `zoom`。
- 光标件会在某几帧盖住屏上文字——拟真行为，横竖版同判，不算缺陷。
- 光标坐标是画幅归一化，配取景键时按落定键换算源图像素 → 屏位置，且**只在 hold 段落点**（微推段落点会漂）。
